# 第三轮审计修复核验

日期：2026-09-09。审查当前未提交工作区，对照[首轮 16 项发现](./项目审计文档-2026-09-09.md)和[第二轮 R-01～R-09](./项目复审报告-2026-09-09.md)。源码指纹见[本轮清单](./audit/2026-09-09-final-recheck/review-manifest.json)。

## 结论

**尚未全部修复。** 本轮修改有效修复了 DNS 超时直接跳过回滚、读回异常直接报成功、DNS2 单独输入被忽略、两种已复现的网卡草稿污染，以及坏历史项清空整批记录等问题。8 个 Rust 单元测试、前端类型检查、生产构建、Tauri 配置检查和严格 Clippy 均通过。

仍存在恢复结果误报、复杂或空配置恢复不完整、路由查询异常被吞掉、可信路径缺口、超时后后代仍存活、稳定网卡身份缺失等问题。依赖与发布物没有更新，格式检查还有两处差异。不能用编译成功代替网络修改与恢复的验收。

本轮只新增复核文档与隔离证据，未修改业务源码、依赖或本机网络。没有启动发布 EXE、执行真实 netsh 配置或进行管理员网络操作。

## 本轮残留发现

### F-01 / P1：回滚成功仍取决于命令返回值，没有验证恢复现场

对应 R-03、A-03。位置：`src-tauri/src/platform.rs:743–754、794–805、873–884`。

`rolled_back` 仍由 `rollback_snapshot(...).is_ok()` 决定。虽然之后读取了快照，却未与 before 比较；读取失败也不会撤销“恢复成功”的结论。模拟 DNS 超时后恢复命令返回成功、实际 IP 仍为新地址 `192.0.2.20`（原值 `192.0.2.10`），结果仍为 `rolledBack: true`，提示“已自动回滚全部配置至修改前状态”。读回完全不可用时也返回回滚成功。

恢复内容还不完整：`platform.rs:527` 仅处理第一个网关，其他默认路由与 metric 未保存/恢复；原本无静态地址时没有清除新 IP 的恢复步骤；`641–655` 对“静态且无 DNS”改成自动 DNS，并丢弃这一步的错误。隔离测试令此 DNS 恢复返回 Err，函数仍返回 Ok。

已改善：多个地址和全部 DNS 会生成恢复命令，普通 DNS 恢复错误不再丢弃，DHCP IP 与静态 DNS 已分开建模。尚无持久恢复记录。

修复要求：恢复后严格比较原快照；原配置无法完整恢复时在写入前拒绝，或补足模型和恢复步骤。区分恢复成功、恢复失败与状态未知；清除无配置状态时也须检查执行结果。

### F-02 / P1：路由查询失败仍伪装为“没有网关”

对应 R-07、A-05。位置：`src-tauri/src/platform.rs:241–246、267–278、401–431`。

`Get-NetRoute` 的 catch 无条件忽略异常。模拟网络服务查询失败，实际固定快照脚本依然成功返回 `gateways: []`，错误快照随后可被用作恢复依据。DNS 模式的注册表读取也仍使用 `SilentlyContinue`，出错时可能默认为自动；Rust 对缺失字段继续默认填充，前缀仍先窄化再校验。

已改善：DNS、DHCP 查询异常会抛错；IP 查询仅放过部分按消息匹配的“无记录”错误。

修复要求：按错误类别区分无记录与查询失败，拒绝不完整快照；DNS 模式查询失败不应猜测。严格校验 DTO 必需字段和原始前缀范围。

### F-03 / P1（条件性）：程序路径仍可受启动环境影响

对应 R-06、A-12。位置：`src-tauri/src/platform.rs:21–34、70–76`。

PowerShell/netsh 仍优先使用进程环境 `SystemRoot`。候选路径只要绝对且存在便被信任，不能防止受控环境指向另一个目录。新增的 `Command::new("taskkill")` 又引入短名称程序搜索入口。硬编码 `C:\Windows` 回退消除了旧版“候选不存在时回退 netsh.exe”的反例，但没有建立可信系统目录来源。

这是需要启动环境或程序搜索位置受控的条件性风险，本轮没有执行恶意程序或证明提权链。修复应通过 Windows API 确定系统目录、考虑 32/64 位重定向，并覆盖所有辅助程序。

### F-04 / P1：总超时返回后仍可能遗留后代进程

对应 R-05、A-04。位置：`src-tauri/src/platform.rs:67–77、155–162、177–203`。

新增 `recv_timeout` 已解决旧版输出 join 等待约 2 秒的问题，输出缓冲也限制为每流 2 MiB。但本轮实际无害进程测试：预算 500 ms，约 **619 ms** 返回超时；父进程退出后，后代仍在约 2 秒时写出完成标记，证明超时返回时进程树没有被完整终止。

当前通过已退出父进程的 PID 调用 taskkill，忽略结果，且 taskkill 自身的 `wait()` 无超时。读取/写入线程也未统一回收。真实写入后代若仍运行，可能与恢复操作交错；本轮仅复现计时进程存活，没有修改网络。

修复要求：用 Job Object 等机制从启动时管理后代生命周期，总 deadline 覆盖清理过程；确认终止后再回滚，不以发出 kill 请求代替终止完成。

### F-05 / P1：读回校验仍未覆盖 DNS 顺序、DNS 模式和网卡身份

对应 R-02、A-03/A-08。位置：`src-tauri/src/platform.rs:819–840`。

两个 DNS 分别用 `any()` 判断是否存在，未检查首选/备用顺序；只检查 IP DHCP，未检查新增的 `dns_dhcp_enabled`；也不比较 before/after 的 GUID。补充模拟将两条 DNS 对调、DNS 模式保留自动、GUID 改为另一个值，只要地址和所需网关存在，仍返回“已成功应用并通过读回校验”。这是隔离控制流证据，不是已发生的系统网卡替换事件。

空网关与空 DNS 的操作语义仍不完整。所谓“最多 3 秒”只约束循环入口，内部一次快照最多还会等待 10 秒。

修复要求：按显式变更计划比较顺序、模式、身份和保留/删除语义，向内部查询传递剩余时间。

### F-06 / P1：历史目标不存在时，仍静默套用到当前网卡

对应 R-04、A-08。位置：`src/composables/useNetworkConfig.ts:266–268、132–141`，以及 `platform.rs:701、710`。

历史条目指定的网卡已删除/改名时，`fillFromHistory` 自动回退到当前选择。隔离测试在 A 上载入 `deleted-adapter` 的历史，表单成为 `{adapter: 'A', ip: '203.0.113.30'}`，没有要求重新选择目标。应明确区分“为原网卡恢复历史”和“将预设应用到别的网卡”，提供目标确认后再复用。

缓存切换还会留下另一块网卡的状态：A→B→A，表单目标是 A，但 `currentSnapshot.adapterName` 仍为 B。前后端依然以名称提交，没有稳定 GUID + revision 绑定。

已修复的两个旧反例不再成立：切换到 B 且查询失败会清空字段、阻止旧 IP 提交；从 A 加载 B 历史能保留历史值并保护 A 草稿。现有请求序号保护也是有效改进。

### F-07 / P2：跨进程锁仍不覆盖跨登录会话，并缺少废弃锁处理

对应 R-08。位置：`src-tauri/src/lib.rs:49–57、106–108`。

新增命名互斥量可以保护同一 Windows 会话的应用实例。但名称使用 `Local\`，不同登录会话仍有独立锁，不能称为机器范围的全局锁。[微软命名空间说明](https://learn.microsoft.com/en-us/windows/win32/termserv/kernel-object-namespaces)

`WAIT_ABANDONED` 也落入普通错误分支；该返回值意味着调用线程已经获得锁，应检查被保护状态的一致性，并确保释放所有权。当前没有相应恢复流程。[微软 WaitForSingleObject 返回值说明](https://learn.microsoft.com/en-us/windows/win32/api/synchapi/nf-synchapi-waitforsingleobject)

本项是源码/API 语义核验，未实测跨会话网络写入。应明确支持范围与 ACL，补废弃锁和多进程测试；仍需基线检查以发现其他系统工具的修改。

### F-08 / P2：历史 schema 和迁移故障处理尚有缺口

对应 R-09、A-10。位置：`src/composables/useConfigHistory.ts:32、78–82、101–107`。

未知未来版本会被过滤，但条件 `schemaVersion > 1` 仍允许负数和小数版本被重标为 1；地址字段只检查非空，没有长度和语义限制。迁移持久化失败仍被静默忽略，不能保证迁移幂等或让用户知道失败。

本轮主要旧反例已修复：数字网关记录被单独过滤，有效项保留；版本 999 不再被重标；上限 10 条和删除失败警告有效。应仅接受明确支持的版本，并对迁移异常给出独立警告。
