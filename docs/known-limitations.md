# Windows 网络配置工具已知限制与技术边界

更新日期：2026-09-10  
适用版本：v0.1.0 (Windows x64)

本文档归纳当前 Windows 网络配置工具在架构、系统权限、事务恢复、底层协议和运行环境等方面的已知技术边界与限制。

---

## 1. 系统权限与提权模型 (UAC)

1. **非自动提权应用**：
   - 本应用为常规 Windows GUI 桌面程序，未在程序清单（Manifest）中强制配置 `requireAdministrator`，亦未引入后台特权代理服务（Privilege Helper Service）。
   - 修改 Windows 网络适配器、IP、DNS、IPv6 及系统 DoH 必须具备管理员权限。普通用户权限下读取网卡信息正常，但执行配置写入将被系统拒绝。
   - **正确用法**：需用户右键可执行文件并选择**“以管理员身份运行”**。
2. **安装器提权 vs 应用提权**：
   - MSI 和 NSIS 安装包在安装阶段触发的 UAC 提示仅用于向 `Program Files` 写入文件和创建桌面/开始菜单快捷方式。
   - 安装完成后从桌面快捷方式直接双击启动程序，Windows 仍以当前登录用户的标准权限运行，不会自动继承安装器的管理员权限。

---

## 2. 事务模型与补偿恢复边界

1. **非操作系统级原子事务**：
   - Windows 原生未提供跨网卡多网络栈的原子事务提交/回滚 API。
   - 本工具实现的“回滚”是应用层内存状态机驱动的**逆向补偿机制**（Compensating Actions）。
2. **无持久化事务日志（No Persistent WAL）**：
   - 变更过程中的现场快照、已触及地址登记和补偿序列均驻留在主进程内存中。
   - 若配置写入过程中程序遭遇强制终止（如任务管理器结束进程、断电、系统崩溃），未完成的补偿逻辑无法在下次启动时自动续行，需用户在 Windows 系统网络设置中人工核验与修复。
3. **复杂网络与路由属性的建模范围**：
   - 当前快照与恢复覆盖单网卡的 IPv4 地址、掩码、网关、IPv4 DNS、DoH 设置、IPv6 绑定开关、IPv6 地址/前缀/来源及 IPv6 DNS。
   - 以下底层属性未纳入完整恢复建模：
     - 单网卡绑定多个辅助静态 IP 或别名地址的高级路由属性；
     - 自定义接口跃点数（InterfaceMetric）与单路由跃点数（RouteMetric）；
     - PolicyStore 路由策略与 SkipAsSource 标志；
     - 复杂多网关路由表的细粒度度量值（辅助网关恢复时按递增缺省 metric 重建）；
     - 未绑定或显式禁用 IPv6 的适配器在 Windows 内核中无 `MSFT_NetIPInterface` 实例，程序会识别其为未启用状态，用户在界面开启 IPv6 时才通过 `Enable-NetAdapterBinding` 重新绑定协议栈。
4. **动态地址（DHCP / SLAAC）恢复特性**：
   - 当由静态模式回滚恢复为 DHCP / 自动获取时，程序向系统发出开启 DHCP/自动配置命令，动态 IP 的获取取决于路由器或 DHCP 服务器的响应。
   - 恢复校验确认该网卡重新处于自动获取状态且原静态污染已被清除，但不强制断言重新获取的动态 IP 字符串与配置前完全一致。

## 3. 系统级 DNS over HTTPS (DoH) 的影响范围

1. **系统全局 DoH 注册表**：
   - Windows 11 / Windows Server 2022 中的 `Set-DnsClientDohServerAddress` 是操作系统全局生效的 DoH 映射表，而非网卡私有属性。
   - 为某一网卡设置指定 DNS 服务器（如 `1.1.1.1`）的 DoH 模板后，系统内其他指向该 DNS IP 的网卡同样可能触发 DoH 加密解析。
2. **操作系统版本依赖**：
   - 原生系统 DoH 配置命令仅在 Windows 10 Build 19616+ 及 Windows 11 上受系统支持。
   - 在旧版 Windows 10（如 21H2 早期或 1909 等）或精简版系统上，检测到不支持 DoH 时，DoH 配置选项将被跳过或提示系统不支持。
3. **DoH 自动升级与明文回退**：
   - 自动模式下系统依据系统内置已知 DoH 列表协商；手动模式要求提供标准 HTTPS 模板。
   - 当启用“允许回退到明文”时，在 DoH 连接阻断或 TLS 协商失败时系统将降级为传统 UDP/TCP 53 端口解析。

---

## 4. 进程并发与互斥体 (Mutex)

1. **命名互斥体设计**：
   - 采用 `Global\tauri_network_config_tool_mutex` 全局互斥体配合进程内异步锁，防止用户多开程序或双击连击导致对同一网卡发起竞争修改。
2. **跨会话与安全沙箱限制**：
   - 在部分严格隔离的受限权限环境或容器中，非提权用户创建 `Global\` 前缀互斥体可能因权限受限（AccessDenied）而回退到 `Local\` 本地会话互斥体。
   - 在此极端场景下，跨不同 Windows 用户会话的同时运行可能无法完全形成全局互斥。

---

## 5. 子进程管理与 Windows Job Object

1. **静默执行与窗口抑制**：
   - 底层调用 `powershell.exe` 和 `netsh.exe` 时统一配置 `CREATE_NO_WINDOW` 标志，并通过 Windows Job Object 将子进程挂载到作业对象中，配置 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`。
2. **极端超时终止边界**：
   - 若进程运行在已受到宿主 Job Object 深度嵌套限制的特权环境，Windows 偶尔会拒绝二次嵌套 Job Object。此时程序会降级使用常规 ProcessId 杀进程机制处理超时。

---

## 6. 前端状态、历史记录与草稿机制

1. **配置历史存储**：
   - 配置历史保存在当前应用运行环境的 WebView2 `localStorage` 中（键名：`net_config_history_v1`），上限 10 条。
   - 历史记录非跨设备同步，也不作为持久化系统备份方案。
2. **网卡草稿机制**：
   - 在界面中切换不同网卡时填写的未提交表单保存在前端内存中；完全退出程序后未提交草稿不保留。
3. **历史记录载入语义**：
   - 载入历史仅回填表单字段，不修改当前已读出的网卡实时物理快照，并会自动向后端重新校验目标网卡是否存在。
