# Windows 网络配置工具项目审计文档

审计日期：2026-09-09（Asia/Shanghai）  
基线提交：`2c6fdafbfb46aca96e68aa8eaffc5ea728f3d4de`  
配套方案：[项目重构报告](./项目重构报告-2026-09-09.md)

## 1. 结论

项目适合继续沿用 Vue + Rust + Tauri，优先修复网络操作边界和构建流程。当前最重要的风险是：**PowerShell 参数拼接形成代码注入入口、配置变更缺少回滚与读回确认、同步系统命令可能阻塞界面，以及 Tauri 配置无法通过当前锁定 CLI 的校验。** 在这些问题解决之前，不建议把现有源码直接作为新的稳定版本发布。

本次共整理 16 项发现。编号表示独立整改工作，不表示 16 个可远程利用漏洞。依赖公告另行去重统计，不能与业务缺陷数量相加作为“漏洞总数”。

前端实际构建较小，现阶段没有证据支持更换 Vue 或引入复杂状态管理来提升性能。更值得投入的是减少 PowerShell 进程启动次数、将阻塞工作移出 UI 线程、建立可恢复的配置变更流程。

### 2.3 评级方法

严重程度描述潜在影响；优先级描述项目实施顺序，两者分开：

| 优先级 | 处理时机 |
|---|---|

## 3. 项目现状

实际调用链为：`src/main.ts → App.vue → invoke → lib.rs 的三个网络命令 → PowerShell/netsh → Windows 网络配置`。历史记录写入 WebView 的 localStorage。Rust 还注册了未在主界面使用的 `greet`。

| 项目 | 声明/实际锁定版本或状态 |
|---|---|
| Vue | 声明 `^3.4.21`，锁定 **3.5.13** |
| Vite / TypeScript / vue-tsc | **6.3.2 / 5.8.3 / 2.2.8** |
| JS Tauri API / CLI | **1.6.0 / 1.6.3** |
| Rust tauri / tauri-build / tauri-utils | **1.8.2 / 1.5.6 / 1.6.2** |
| wry / webview2-com | **0.24.11 / 0.19.1** |
| 包管理器 | Yarn Classic **1.22.22**，有 yarn.lock 和 Cargo.lock |
| 主体规模 | App.vue 397 行，lib.rs 371 行；另有一份未被入口引用的 App2.vue |
| 测试与 CI | 现有跟踪文件中未见测试套件、GitHub Actions 工作流；本次新增的审计复现脚本不算产品回归套件 |

值得保留的做法：前后端都检查 IPv4 字符串；netsh 使用独立参数数组而非 cmd.exe；PowerShell 带 `-NoProfile`；Rust 正则使用 OnceLock 缓存；前端主要使用 Vue 文本插值；内置 shell 权限已关闭；正常保存路径限制历史为 10 条。这些措施有价值，但不能替代下面缺失的边界。

## 5. 详细发现与整改验收

### A-01：适配器名称形成 PowerShell 代码注入入口

**依据：** `src-tauri/src/lib.rs:95、131、148、235`，读取 IP、网关、DNS 和检查网卡状态时，均用 `format!` 将 IPC 参数直接插入 PowerShell 单引号字符串。后端对名称只检查非空。

名称一旦包含单引号，就能结束字符串。例如审计脚本把 `Ethernet'; Write-Output AUDIT_MARKER; #` 代入状态查询模板；PowerShell Parser 返回 **0 个语法错误、两个命令节点 Get-NetAdapter 与 Write-Output**。生成脚本未被执行。见 [AST 结果](./audit/2026-09-09/injection-ast.json) 和 [复现脚本](./audit/2026-09-09/parse-injection.ps1)。

攻击前提是能控制进入 IPC 的名称，例如受控前端脚本、被污染的历史数据或恶意名称经界面进入命令。正常下拉选择不是可靠的后端信任边界。若宿主被用户以管理员身份启动，注入代码继承相同权限；本次没有证明公网远程入口或完整提权链。

**整改：** 前端提交稳定网卡 GUID/标识，后端重新枚举并精确解析到当前 interface index；拒绝不存在或不匹配的目标。固定 PowerShell 脚本，通过 JSON stdin 传递数据并解析，不再生成脚本文本；或者用 Windows API。保留 netsh 时仍须处理其自身参数语法。仅使用 Base64 `-EncodedCommand` 不能消除字符串拼接注入，关闭 Tauri 内置 shell API 也不能约束 Rust 自定义命令。

**验收：** 单引号、双引号、分号、反引号、换行、通配符和中文名称都作为普通数据处理；无论绕过 UI 如何调用 IPC，都不能产生额外脚本语句；对不存在 GUID 不创建写进程。

### A-02：当前 Tauri 配置阻断 CLI

**依据：** `src-tauri/tauri.conf.json:84–87` 的 `tauri.bundle.windows.security` 和 `requestedExecutionLevel` 不属于锁定 CLI 识别的字段。实际执行 `node node_modules/@tauri-apps/cli/tauri.js info` 返回：

```text
Additional properties are not allowed ('requestedExecutionLevel', 'security' were unexpected)
```

`src-tauri/capabilities/default.json` 是 v2 风格，依赖却全部使用 Tauri 1；它不能为当前应用提供 v2 权限保护。其中 `opener:default` 也没有相应插件安装依据。管理员权限字段写在无效位置，不能据此宣称应用已正确嵌入 UAC manifest。

**整改：** 先恢复单一、可验证的 Tauri 1 配置基线，再独立迁移 Tauri 2；或在明确的迁移分支一次性协调更新配置、Cargo、JS API 和 CLI。权限声明应通过对应版本的合法 manifest/构建机制配置，并检查最终 PE manifest。

**验收：** CLI info、开发启动、release 构建和 MSI 打包通过；检查成品执行级别。不能用仓库旧 EXE 可运行来代替源码重建。

### A-03：应用配置不是可恢复操作

**依据：** `lib.rs:252–317` 依次修改 IP、主 DNS、辅助 DNS，任一步失败立即返回；之前成功的步骤不会恢复。成功依据仅为子进程退出码，没有读取系统确认；后端也没有修改锁。`Ipv4Config` 没有 DHCP/静态模式、多地址、路由 metric 等恢复所需信息。

此外，`dns1` 为空时整个 DNS 分支跳过，即使传入 `dns2` 也不会设置；空 DNS 到底表示保留、清空还是恢复自动获取并未成为明确接口约定。空网关参数被省略，其系统实际效果也需要验证。

**整改：** 建立“读取完整快照 → 校验 → 生成变更计划 → 串行应用 → 读回比较 → 确认/恢复”的流程。采用 `Keep/Automatic/Static` 等显式操作语义，避免让空字符串承担多重含义。持久化恢复记录并报告每一步结果；系统命令并不提供数据库事务，回滚本身也可能失败，界面必须如实展示。

**验收：** 在虚拟机第二/第三步故障注入、拒绝 UAC、进程退出、网卡拔出和并发修改场景下，不误报成功；能恢复或给出明确的恢复失败状态、原始配置和人工处理步骤。

### A-04：同步阻塞与进程启动成本

**依据：** `lib.rs:19、89、184` 都是同步 Tauri 命令，内部使用阻塞 `.output()`，无超时、取消及子进程清理机制。Tauri 1 官方说明普通同步命令在主线程执行。读取配置顺序启动 **3 个 PowerShell**；一次完整静态配置写入最多启动 **1 个 PowerShell + 3 个 netsh**。[Tauri 命令执行说明](https://v1.tauri.app/v1/guides/features/command/)

**整改：** 使用异步命令，并将阻塞 API 放进受控 `spawn_blocking` 或专用 worker；外部进程使用可管理的异步句柄。合并读取为一个返回完整 JSON 的脚本，最终可切换原生 API。超时应终止并回收子进程，必要时用 Windows Job Object 管理进程树；仅对 future 加 timeout 不会自动停止底层阻塞操作。先把所有写操作串行化，再考虑按网卡锁优化。

**验收：** 模拟 30 秒挂起的子进程时 UI 仍能响应；在规定时限内返回可识别超时错误，没有孤儿写进程；记录 p50/p95 和进程数，而非只报告“感觉更快”。

### A-05：网络状态读取模型不完整

**依据：** `lib.rs:110–121` 假设 `ConvertTo-Json` 返回单对象，而多 IPv4 地址返回数组，因此 `ip_info["IPAddress"].as_str()` 会失败；无地址时也缺少“未配置”的正常结果。`141–145` 把多个默认路由 NextHop 合并为含换行字符串，`158–167` 只保留两个 DNS。网关/DNS 查询失败被转换为空值，用户无法区分“无配置”和“读取失败”。

**整改：** 用显式 `Vec` DTO 返回地址、前缀、地址状态、默认路由及 metric、DNS 列表和 DHCP 状态；统一 JSON 数组形状、UTF-8、退出码与 `$ErrorActionPreference='Stop'`。仅在确认为不存在时返回空数组。前缀先检查 `0..=32` 再窄化转换。

**验收：** 0/1/多个地址、多个默认路由、3 个以上 DNS、无网关、无网络服务、中文名称均有确定结果。界面只编辑单地址时，应显示其他地址并明确变更范围。

### A-06：格式校验没有覆盖网络语义

**依据：** `lib.rs:203、342` 和 `App.vue:98、137` 将掩码当普通 IPv4 字符串校验，`255.0.255.0` 可通过。Rust 正则允许前导零，前端拒绝，隔离检查验证了此差异。后端还把“已启用但网线未连接”的 `Disconnected` 状态与不能配置混为一谈（`lib.rs:246–248`）。

**整改：** Rust 使用 `std::net::Ipv4Addr` 和前缀长度作为权威模型；统一 trim/规范化策略。检查连续掩码、地址用途及网关可达策略；对于 /31、/32、点对点、特殊路由等允许业务明确例外，不机械套用普通子网规则。区分管理状态与链路状态。模式决定哪些字段必填，DNS2 单独填写必须有明确处理。

**验收：** 参数化测试覆盖连续/非连续掩码、前导零、空白、特殊地址、网关跨网段策略、/31、/32、断链但已启用适配器；前端提示与后端最终结果一致。

### A-07：可选字段实际上无法留空提交

**依据：** `App.vue:232–234` 给 gateway、dns1、dns2 都写了 HTML `required`，但校验函数与 Rust 注释允许这些字段为空。浏览器约束校验会阻止普通表单提交，辅助 DNS 也被迫填写。

**整改与验收：** 基于明确的地址/DNS 模式设置必填规则；真实表单测试验证无辅助 DNS、无默认网关可正常提交。给输入框增加关联 label，校验错误定位到字段，状态区使用适当的 `aria-live`。

### A-08：草稿可被无意应用到另一块网卡

**依据：** `App.vue:222` 仅修改 `selectedAdapter`，没有重置或重新读取字段；`162–164` 提交时又把当前所选名称赋给旧的 `ipConfig`。用户在 A 网卡读取配置后切换 B，可把 A 的 IP/DNS 写到 B。当前禁用控件能减少请求期间的正常交互竞争，但不能解决切换后的旧数据问题。

**整改：** 草稿绑定稳定 adapter ID 和原始快照 revision。切换时提示处理未保存修改并重新读取；写入前显示网卡与配置差异。后端再次检查目标和基线，不把下拉框值视为既有授权。

**验收：** A/B 网卡切换、历史载入后网卡已删除/改名、读请求过期返回时，不串写配置；多个应用实例发起写入时也不得交叉覆盖。

### A-09：持久化异常导致错误的操作结果

**依据：** `App.vue:163–169` 在网络应用成功之后调用 `saveConfig()`；其 `79` 行的 localStorage 写入可能抛错，最终被 catch 变成“应用失败”。成功提示本身也会被“配置已保存”覆盖。隔离 IPC 成功一次、storage 抛 quota 错误时，实际观察到“应用失败：fixture quota exceeded”。[复现结果](./audit/2026-09-09/frontend-observations.json)

**整改与验收：** 网络应用结果和历史持久化结果分开处理。网络成功但历史失败显示“配置已应用，历史保存失败”，不得诱导用户重试有副作用的操作；缓存结果绑定提交时的不可变配置快照。

### A-10：历史数据不能作为可信 IpConfig

**依据：** `App.vue:83–95` 仅检查最外层是否数组；`[null]` 会被接受，随后填入报错；加载 12 条仍为 12 条。`saveConfig` 只弹出一条旧记录，无法修复已超限数据。`175–181` 直接消费元素，缺少 schema、长度限制及版本字段。

**整改：** 读取时逐项验证、规范化和截断；损坏数据隔离备份并告知用户。保存预设与成功应用历史分别建模，加入 schemaVersion、时间和稳定网卡标识。10 条小数据可继续用 localStorage；引入插件存储并不会自动获得加密、验证或安全隔离。

**验收：** 空值、缺字段、超长值、非字符串、未知版本、配额失败均可恢复。旧数据迁移幂等。网络地址属于本地环境信息，诊断导出需脱敏并提供清除入口。

### A-11：CSP 与权限边界缺少纵深保护

**依据：** `tauri.conf.json:90–91` 的有效安全配置 `csp: null`；`8` 行开启全局 Tauri API；运行文档要求管理员启动。已关闭内置 shell allowlist，但网络修改是自行注册的 Rust 命令，不受该开关保护。

这是条件性风险：当前源码未见 `v-html`、远端页面加载或已证实的 XSS 路径；不能把 CSP 缺失本身写成“存在 XSS”。无效 UAC 字段也不能证明成品默认提权。

**整改：** 部署与开发使用分别验证的 CSP，只开放实际资源和 IPC 所需来源；去掉不需要的全局 API 暴露和窗口/对话框权限。中期改为普通权限 UI + 按需提升的最小写入 helper，helper 接口仅接受结构化配置。Tauri 2 的 capability 不会自动保护所有应用自定义命令，需要显式纳入命令权限体系。[CSP](https://v2.tauri.app/security/csp/)；[自定义命令与 capabilities](https://v2.tauri.app/security/capabilities/)

**验收：** 未授权窗口不能调用写命令；无远程 IPC 授权；普通读取不需提权；资源仍正常显示。helper 验证调用身份、请求来源、目标网卡和输入，不提供任意 shell 功能。

### A-12：系统程序路径未固定

**依据：** `lib.rs:21、100、136、153、237、252、277、300` 使用 `Command::new("powershell")` / `Command::new("netsh")`。路径解析依赖环境及 Windows 程序搜索规则。若可写目录或 PATH 中存在优先匹配的同名程序，可能执行错误二进制；管理员运行会扩大影响。本次未创建同名 EXE 或验证实际劫持。

**整改与验收：** 使用系统 API 确定可信系统目录，固定绝对路径；正确处理 32/64 位重定向，不仅依赖可修改环境变量。固定工作目录、最小环境、非交互模式；在受控 VM 中验证非可信目录的同名程序不会被调用。

### A-14：构建与文档不一致

**依据：** `package.json:13–14` 引用不存在的 `build.js` 和 `package.js`；`build-app.bat:11–22` 未检查构建退出码，仍输出完成；中英文开发文档和打包说明把 `--target app/msi` 当包格式。当前 CLI `build --help` 明确 `--target` 是架构 triple，`--bundles` 才是包格式，`app` 也不是 Windows 便携 EXE 的含义。

开发文档示例传 `adapter_name`，真实前端传 `adapterName`；后者符合默认 Tauri 参数命名规则。历史列表的“应用”按钮实际只填充表单，README 的“一键切换”容易误导。所谓“系统 API 获取”实际上主要通过 PowerShell 外部进程完成。

**整改与验收：** 统一一个发布入口，失败立即退出；便携构建使用对应 CLI 的 `--bundles none`，MSI 用 `--bundles msi`，32 位通过 `--target i686-pc-windows-msvc`。这些是配置修复后的指令方向，本次没有完成原生打包。保留旧文档但加版本说明，所有复制即用的命令在干净 Windows CI 中验证。

### A-15：发布可信度与兼容性

**依据：** 当前仓库 EXE 大小 **2,396,672 字节**，`Get-AuthenticodeSignature` 返回 **NotSigned**；`tauri.conf.json:75` 无证书配置。仓库没有可关联提交、锁文件和成品的发布流水线。`webviewInstallMode` 是 `downloadBootstrapper`，README 的便携说明未说明 WebView2 依赖；`vite.config.ts:45` 使用 `esnext`，缺少最低 WebView 支持约定。

**整改：** 发布工件移到 Release/制品存储，建立签名、SHA-256、SBOM 和构建来源记录；签名密钥只存受控 CI secret。确定 Windows 与 WebView2 最低版本，验证全新和离线机器场景。便携 EXE 不能自动等同于包含 WebView2 runtime。当前不需要为了现代化强行启用自动更新。

**验收：** 从干净检出生成签名工件，验证签名/时间戳/哈希；在线安装、已有 runtime、无 runtime、离线环境行为都有说明；旧成品保留但不得冒充新提交的构建结果。

### A-16：维护成本与质量门禁

**依据：** App.vue 同时承担 IPC、校验、历史、表单和提示；lib.rs 同时负责 DTO、系统进程、解析和业务决策。App2.vue 重复实现已漂移，未被 main.ts 导入；`src/tauri.d.ts` 手写宽泛 invoke 声明，不能验证命令和 payload。错误依赖字符串是否含“失败”来决定颜色。`cargo fmt --check` 返回格式差异。

README 展示 MIT 标记并链接 LICENSE，但基线跟踪文件未见 LICENSE。这个事实属于文档/发布完整性缺口，不在本报告中作许可法律判断。

**整改与验收：** 按功能拆分少量模块，统一错误 DTO 和请求状态机；清理备用代码前确认用途。Rust DTO 可生成 TS 类型，但仍须运行时校验。补上真正的回归测试、格式与 lint、依赖扫描和 Windows 构建门禁；浏览器开发使用显式 mock backend。许可证声明应由维护者确认并补齐对应文件。
